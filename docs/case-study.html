Product case study · functional prototype · synthetic catalog

One filter for Berlin WBS listings — tested as an end-to-end Telegram prototype.

FlatFeed normalizes inconsistent listing text and compares four renter criteria with explicit rules. The current version runs end to end on a synthetic catalog; live source coverage, freshness and renter outcomes remain open questions.

WBS (Wohnberechtigungsschein) is a certificate used to qualify for subsidized housing in Berlin. Kaltmiete is rent before utilities.

01Product

A repeated search becomes one explicit, inspectable workflow.

The working hypothesis is that WBS renters lose time checking fragmented listing formats and reapplying the same listing criteria. FlatFeed tests a narrower job: set one filter, then inspect active matches in a consistent format.

02Decisions

I prioritized trust in the core loop over feature breadth.

01

Four fields, not a generic search

The prototype keeps only criteria used in its match decision. Unknown rent or room values fail closed instead of producing a confident-looking match.

02

Rules decide what renters see

Parsing and matching are deterministic, so a match can be explained field by field. Optional AI QA may flag parser drift for an admin, but cannot alter data or user-facing results.

03

Reliability before source count

A synthetic-adapter state check, background-delivery deduplication and deletion of saved filter data are implemented. Live housing-company sources are outside this version.

My contribution

I owned the problem framing, scope, interaction rules, reliability trade-offs and evaluation design. I implemented the bot, dashboard and test harness with Claude Code and Codex as coding collaborators.

03Evidence

The workflow runs. The market value is not yet proven.

I use evidence labels to keep technical completion separate from user validation. This is a functional product prototype, not a launched housing service.

Demonstrated now

  • End-to-end filter, match and Telegram delivery flow
  • Synthetic-adapter state check and background notification deduplication
  • Deterministic matching with field-level reasons
  • 15 authored synthetic cases currently pass the parser regression check

Not demonstrated yet

  • Demand from real WBS renters
  • Coverage and freshness of permitted live sources
  • Time saved or application outcomes
  • Usefulness and false-alarm rate of hosted-model AI QA

The 15-case regression set covers cases I designed; it is a guard against regressions, not proof that arbitrary live listing text will parse correctly.

04Next test

Validate usefulness before expanding the system.

The next step is not more AI or more dashboard features. I would connect one source whose terms permit use, then watch a small group of WBS renters complete the filter-to-listing flow.
